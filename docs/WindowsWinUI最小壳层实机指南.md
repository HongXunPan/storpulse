# Windows WinUI 最小壳层实机指南

## 1. 当前范围

本指南用于在 Windows 10 22H2 x64 标准用户环境验证 StorPulse 阶段 2A WinUI 3 壳层能否启动、虚拟化展示 1,000 行、按列排序并每秒局部刷新 32 行。

当前数据全部在内存中确定性生成，不连接 LocalSystem 服务、不读取 ETW、不写日志、不请求 UAC，也不代表通知区域、单实例、关闭后继续运行、真实采集或 Windows 平台支持已经通过。

## 2. 操作步骤

1. 从成功的 GitHub Actions `Windows 开发者预览服务` 下载名称以 `storpulse-windows-shell-gate-x64-` 开头的 artifact。
2. 完整解压到普通目录，不要直接在压缩包预览器中运行。
3. 确认当前文件管理器或终端没有“以管理员身份运行”。
4. 双击 `运行 WinUI 界面门禁.cmd`；该入口不提升权限，命令行会显示不含路径和用户信息的启动阶段码，窗口关闭后会显示 `exit_code` 并停留等待确认。
5. 不要同时启动第二份，也不要用兼容模式、管理员身份或第三方注入工具改变运行环境。

## 3. 通过条件

- 没有 UAC，WinUI 窗口能够正常出现；
- 顶部明确显示“阶段 2A”和“界面门禁数据”，没有把内存数据标成真实磁盘活动；
- 右上角显示 `1,000 行内存门禁数据`；
- 底部刷新状态持续前进，并显示每次只更新 `32` 行且未产生磁盘写入；
- 快速滚动到列表中后部时没有明显空白、卡死或整页闪烁；
- 点击“应用”“当前读取”“当前写入”“本次累计”能够切换排序；
- 选中一行后切换排序，仍能保持同一门禁进程的选择；
- 关闭窗口后进程退出，命令行最终显示 `exit_code=0`。

关闭后继续运行、通知区域图标和再次唤起窗口属于阶段 2B，本轮关闭即退出是预期行为。

## 4. 反馈内容

若未通过，保留命令行中的最后一个 `stage`，以及出现时的 `failure_source`、`failure_stage`、`exception_type`、`hresult`、`exit_code` 和可见错误文字，并反馈：

- Windows 产品版本、显示版本、内部版本和 x64 架构；
- 是否为标准用户、是否出现 UAC；
- 窗口是否出现，以及失败发生在启动、滚动、排序、选择还是关闭；
- 当前 artifact 对应的提交 SHA。

阶段码和异常码只输出到当前命令行，不写入磁盘；本阶段应用不会生成诊断 ZIP、日志、崩溃转储或自动上传内容。不要提供用户名、完整路径、命令行参数、机器标识或包含其他应用隐私信息的截图。
