# Windows WinUI 最小壳层实机指南

## 1. 当前范围

Windows 10 x64 标准用户已在源码提交 `af0022b` 完成阶段 2B：通知区域原生菜单、关闭后继续运行、再次唤起、单实例重定向和明确退出。本指南保留为已通过门禁的复核步骤；当前阶段 2C 真实采集操作改见[Windows 实时采集界面实机指南](Windows实时采集界面实机指南.md)。

该提交只使用 1,000 行确定性内存数据，不连接 LocalSystem 服务、不读取 ETW、不写运行日志、不请求 UAC。通知区域暂用 Windows 系统默认应用图标，只用于生命周期门禁，不是 StorPulse 正式品牌资产。

## 2. 操作步骤

1. 从成功的 GitHub Actions `Windows 开发者预览服务` 下载名称以 `storpulse-windows-shell-gate-x64-` 开头的 artifact。
2. 完整解压到普通目录，不要直接在压缩包预览器中运行。
3. 确认文件管理器和终端没有“以管理员身份运行”，然后双击 `运行 WinUI 界面门禁.cmd`。
4. 确认没有 UAC，主窗口顶部显示“阶段 2B”，底部刷新次数持续前进。
5. 记住当前刷新次数，点击窗口关闭按钮；窗口应消失，但命令行不得返回 `exit_code`，任务管理器中仍应只有一个 `StorPulse.Windows.App` 进程。
6. 在 Windows 通知区域查找系统默认应用图标；若图标被折叠，先展开隐藏图标。左键或键盘激活图标，确认恢复的是原窗口，而且刷新次数已经继续增长。
7. 保持应用运行，再次双击 `运行 WinUI 界面门禁.cmd`。第二个命令行应显示 `single_instance_redirect_completed` 并返回 `exit_code=0`；已有窗口应被唤起，系统中仍只有一个常驻应用进程。
8. 再次关闭主窗口，右键通知区域图标；原生菜单应包含“打开 StorPulse”和“退出 StorPulse”。选择“打开 StorPulse”验证恢复，再关闭并选择“退出 StorPulse”。
9. 原始命令行应最终显示 `exit_code=0`；应用进程和通知区域图标都应消失。

## 3. 通过条件

- 全程使用标准用户权限，没有 UAC；
- 点击关闭只隐藏窗口，确定性内存刷新继续运行；
- 通知区域图标可以用鼠标和键盘唤起原窗口；
- 原生菜单可以打开窗口和明确退出；
- 第二次启动完成重定向，不留下第二个常驻进程；
- 明确退出后窗口、进程和通知区域图标都不残留；
- 两个命令行最终都显示 `exit_code=0`；
- 没有生成运行日志、诊断 ZIP 或自动上传内容。

若复核时出现关闭窗口导致进程退出、第二次启动留下两个进程、菜单无法退出、明确退出后仍有图标或进程、隐藏期间刷新停止，则阶段 2B 证据失效，应停止阶段 2C。

## 4. 反馈内容

若未通过，保留命令行中的最后一个 `stage`，以及出现时的 `failure_source`、`failure_stage`、`exception_type`、`hresult`、`exception_message`、`framework_message`、`exit_code` 和可见错误文字，并反馈：

- Windows 产品版本、显示版本、内部版本和 x64 架构；
- 是否为标准用户、是否出现 UAC；
- 问题发生在首次启动、关闭隐藏、通知区域唤起、第二次启动、菜单操作还是明确退出；
- 失败时可见的应用进程数量；
- 当前 artifact 对应的提交 SHA。

阶段码和异常详情只输出到当前命令行，不写入磁盘；异常消息会压缩为单行、限制长度，并在检测到路径、SID 等敏感内容时整体替换为脱敏标记。不要提供用户名、完整路径、命令行参数、机器标识或包含其他应用隐私信息的截图。
