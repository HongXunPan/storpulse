# Windows 实时采集界面实机指南

## 1. 当前范围

本指南验证 Windows 阶段 2C 最小真实纵切：标准用户 WinUI 通过 Rust 客户端 DLL 启动已安装的手动 LocalSystem 服务，经产品命名管道接收存储层进程 I/O 原始快照，再交给共享 Rust 引擎聚合并展示应用实时速率、累计量和持续时间。

当前候选范围仅为 Windows 10 x64。Windows 11、签名分发、长期运行、观察会话、历史持久化和桌面日志导出仍未通过；本轮不会把采集失败静默替换成模拟数据，也不会逐样本写日志。

## 2. 验证顺序

1. 从成功的 GitHub Actions `Windows 开发者预览服务` 下载名称以 `storpulse-windows-realtime-gate-x64-` 开头的 artifact，并完整解压到普通目录。
2. 关闭此前运行的 StorPulse。若机器上已安装旧包服务，先双击旧包或当前包的 `卸载 StorPulse 按需服务.cmd`，确认 UAC 后等待卸载窗口显示成功。
3. 双击当前包的 `安装 StorPulse 按需服务.cmd`，确认 UAC；安装成功后关闭管理员窗口。安装和卸载是本轮仅有的 UAC 边界。
4. 从普通文件管理器双击 `运行 Windows 实时采集门禁.cmd`。运行入口不得出现 UAC；命令行应出现 `stage=windows_realtime_collection_started`。
5. 等待主窗口从“正在启动”变为“Windows ETW 实时采集中”。列表行数应来自当前真实应用，而不是固定 1,000 行；顶部来源和完整性必须有明确文字。
6. 打开 Windows 资源监视器的“磁盘”页，然后执行一个可辨认的真实磁盘负载，例如复制一个大文件或让已知应用读取大型本地文件。对照 StorPulse 与资源监视器中的应用名称、主要读写方向和相对活跃程度；不要求两者瞬时数值完全一致。
7. 记住一个活跃应用的累计量，关闭主窗口。窗口应隐藏到通知区域，服务和 `StorPulse.Windows.App` 进程继续运行；重新打开后累计量不得倒退。
8. 保持应用运行，再次双击运行入口。第二个进程应完成单实例重定向后退出，已有窗口被唤起，系统中仍只有一个常驻 `StorPulse.Windows.App`。
9. 从通知区域原生菜单选择“退出 StorPulse”。原始命令行应依次出现 `stage=windows_realtime_collection_stopped`、`stage=application_collection_cleanup_completed` 和 `exit_code=0`。
10. 在普通命令提示符执行 `sc query StorPulseCollector`，确认 `STATE` 为 `STOPPED`；任务管理器中不应残留 StorPulse 应用进程。
11. 验证完成后可运行 `卸载 StorPulse 按需服务.cmd` 清理服务、安装目录和受限诊断目录。

## 3. 通过条件

- 只有安装和卸载出现 UAC，WinUI 始终以标准用户运行；
- 界面展示真实服务与 ETW 数据，采集失败时显示受限或失败，不出现确定性替代数据；
- 真实负载的应用、主要读写方向和相对活跃程度可与资源监视器交叉解释；
- 关闭隐藏期间采集继续，恢复窗口后累计量不倒退；
- 第二次启动只唤起原窗口，不留下第二个常驻进程；
- 明确退出会完成停止协议、ETW 和服务，命令行返回 `exit_code=0`；
- 正常运行不生成逐样本日志、诊断 ZIP、数据库或自动上传内容。

任一前提失败时，停止阶段 2C，不继续观察会话、历史或提醒开发。

## 4. 反馈内容

若未通过，点击包内 `反馈问题.url`，只提供：

- Windows 产品版本、显示版本、内部版本和 x64 架构；
- 当前 artifact 对应的提交 SHA；
- 是否为标准用户、哪个步骤出现 UAC；
- 最后一个 `stage`、`failure_source`、`failure_stage`、`exception_type`、`hresult`、稳定错误码、原生错误码和 `exit_code`；
- 问题发生在安装、连接、实时刷新、关闭隐藏、单实例、明确退出还是服务停止；
- 资源监视器只需反馈应用名称和方向是否一致，不提供文件路径。

不要提供用户名、完整路径、命令行参数、SID、机器标识、原始 ETL、崩溃转储或包含其他应用隐私信息的截图。控制台阶段字段只在当前窗口输出，不主动写入磁盘或上传。
