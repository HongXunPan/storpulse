# Windows 持续采集与诊断契约

## 1. 职责与状态

本文定义 Windows x64 开发者预览的按需服务、持续采集、异常记录、诊断导出和反馈边界。阶段 0 一次性诊断协议的操作说明仍由[Windows 按需服务门禁指南](Windows按需服务门禁指南.md)负责；共享领域输入输出以[共享内核契约](共享内核契约.md)为准。

当前已确认：

- Windows 10 Pro 22H2 x64 按需 LocalSystem 服务最小候选门禁通过；
- Windows 10 与 Windows 11 x64 共用产品实现，但平台证据分别维护；
- Windows 11 尚无本项目实机证据，只能标记目标覆盖；
- 日志默认本地限量保存，由用户主动导出脱敏 ZIP，不自动上传。

当前已完成 `RawSnapshot v2`、持续消息、长度分帧、双端状态机、会话累计快照、Win32 ETW 回调与会话控制、产品字节流命名管道、单客户端鉴权、每秒发布、停止排空、确认闭环，以及产品 SCM 调度与独立服务入口。普通用户客户端、产品安装、WinUI 应用、日志轮转和反馈入口尚未实现；本机只执行纯 Rust 测试与 Windows MSVC 目标交叉检查，Windows EXE 由 GitHub Actions 的 Windows runner 构建，但两者都不替代 Win10 实机持续采集门禁。

## 2. 组件与权限边界

| 组件 | 权限 | 职责 | 禁止事项 |
| --- | --- | --- | --- |
| C#/WinUI 桌面客户端 | 标准用户 | 生命周期、展示、设置、历史、提醒、导出与反馈入口 | 不直接启动 ETW，不以提升权限长期运行 |
| Rust Windows 客户端适配层 | 标准用户进程内 | 服务连接、协议校验、快照归一化与共享内核 FFI | 不接收逐条 ETW 事件，不持久化敏感元数据 |
| Rust 按需服务 | LocalSystem、手动启动 | ETW 会话、进程身份、窗口聚合与安全诊断事件 | 不承载 UI、用户数据库、设置、导出或任意路径写入 |
| Rust 共享内核 | 进程内 | 差值、stale、应用聚合、活动与观察会话 | 不知道 Windows 权限、服务、路径或设备句柄 |

安装、升级和卸载服务时才允许 UAC。服务不开机自启；用户开始观察时由普通客户端启动，最后一个有效会话结束、客户端断开、超时、系统停止或关机时收口 ETW 并退出。未安装或无法连接服务时，客户端显示 `restricted` 或 `unsupported`，不使用广义进程 I/O 冒充磁盘专属读写。

产品服务名固定为 `StorPulseCollector`，独立可执行文件为 `storpulse-windows-service.exe`。SCM 每次启动只接受一个 64 位十六进制 nonce；服务完成单一会话后退出，`STOP` 或系统关机触发的受控取消按正常停止上报，其他协议、鉴权、ETW 或状态上报失败保留为服务错误。

服务继续拒绝远程管道客户端，只允许单一已认证采集会话，直到多用户和并发门禁独立通过。服务命令不得携带输出目录、完整路径、命令行、任意 Provider、访问令牌或任意写文件参数。

## 3. 持续协议与快照

产品协议使用 4 字节小端无符号长度头和 UTF-8 JSON 负载，单帧负载上限为 1 MiB；超限、长度不一致或 JSON 无效均不得进入状态机。消息同时携带协议版本与共享快照版本，状态机固定为：

`disconnected → connecting → ready → collecting → draining → stopped`

任何状态都可以进入 `failed`；失败必须携带稳定阶段、稳定安全错误码和可选 Win32/HRESULT 数值。未知协议版本、越序消息、认证失败、消息过大、超时或客户端断开都立即停止本次会话并清理 ETW。服务端独立校验命令顺序、运行标识、nonce 格式、管道客户端 PID、非提升 token，并拒绝客户端声称已接收尚未发送的未来序号，不信任 JSON 自报身份；允许客户端停止时暂时落后于服务端已写入管道的序号，由后续有序快照和最终序号闭环。

阶段 1 固定每秒一个批量快照，不接受客户端任意调整间隔，不逐事件跨管道或 FFI。每次采集从序号 1 开始并严格连续，快照单调时间必须前进；停止响应必须回显最后序号。服务按 `PID + 启动时间` 聚合会话内累计读写，并同时提供：

- 捕获时间、单调时间、数据源、范围、新鲜度与完整性；
- 进程身份、父进程、最小可执行名称和非敏感应用归并元数据；
- 会话内设备与进程累计读写和可用的操作次数；
- 受限、已退出、无法归因、事件丢失、采集耗时和服务开销摘要。

共享 `RawSnapshot` 已升级为 `schemaVersion=2`：设备使用会话内稳定、平台命名空间化且不包含序列号的 `deviceId` 字符串；macOS 使用 `macos:ioreg:<十进制注册表项 ID>`，Windows 使用 `windows:disk:<会话磁盘编号>`，不得让 Windows 磁盘编号伪装成 IORegistry ID。

客户端只把通过协议和隐私校验的完整快照交给共享内核。超时、断连或失败时发布 stale/failed 状态，不沿用旧速率，也不构造零值快照。客户端发出停止请求后进入 `draining`，仍可接收服务停止 ETW 后产生的一份最终排空快照，再以其序号校验 `stopped` 并回送确认。

运行时对设备和进程累计量使用饱和加法；已退出进程至少保留到下一次快照后再清理，PID 复用以新的启动时间建立新身份。无法读取的 CPU、内存和物理占用字段使用 `null` 或省略，事件映射失败、进程受限或 ETW 丢失会把快照降为 `partial`。

产品管道固定为 `\\.\pipe\StorPulse.Collector.v1`，使用本地单实例字节流和分段读写，不复用阶段 0 的 64 KiB 消息管道；继续拒绝远程客户端，并保留中等完整性标准用户所需的最小数据读写权限。ETW 回调不阻塞等待聚合器，有界通道饱和或经典事件负载无法安全解码时累计为事件丢失。

线程和磁盘高频字段按经典内核事件 MOF 布局读取；进程低频字段通过 TDH 读取后立即裁成最小可执行名称，不读取命令行或 SID。进程身份优先使用 `GetProcessTimes` 的创建时间；仅新建事件在进程已瞬时退出时使用 ETW 已转换为 FILETIME 的事件时间，启动枚举无法确认身份时标记为受限。

## 4. 结构化异常事件

普通运行只记录组件生命周期、状态转换、警告和错误，禁止逐样本日志。客户端、适配层和服务使用同一 `runId`；每条 NDJSON 事件至少包含：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 诊断事件版本 |
| `timestampUtc` / `monotonicMilliseconds` | 墙钟和相对时序 |
| `runId` | 本次应用运行关联标识 |
| `component` | `app`、`adapter`、`service`、`engine` 或 `storage` |
| `phase` / `event` / `severity` | 稳定阶段、事件与级别 |
| `safeErrorCode` | 不含本机文本的稳定错误码 |
| `nativeCode` | 可选 Win32/HRESULT 数值 |
| `appVersion` / `serviceVersion` / `protocolVersion` | 版本关联 |
| `osProduct` / `osBuild` / `architecture` | 平台能力定位 |
| `state` | 服务、ETW、管道、存储或导出聚合状态 |

默认禁止记录用户名、SID、完整路径、命令行、文件内容、原始事件负载、nonce、访问令牌、管道秘密、任意环境变量、未经清洗的异常消息和原始调用栈。Rust panic 与 .NET 未处理异常只落稳定类型、组件和安全错误码；崩溃转储默认关闭。

## 5. 本地存储与写入预算

桌面客户端在 `%LocalAppData%\StorPulse\Diagnostics` 保存最多 5 个事件文件，每个不超过 1 MiB。写入只由生命周期、警告或错误触发，不按采样周期刷新；历史关闭时不得因为正常采集产生周期性日志写入。

服务正常事件优先保存在有界内存环并经认证管道交给客户端。只有发生无法交付给客户端的终止失败时，服务才在 `%ProgramData%\StorPulse\Diagnostics` 原子写入一条不超过 64 KiB 的安全失败记录；最多保留 16 条，按时间淘汰。客户端只读导入这些记录，服务不得打开用户历史数据库。

所有轮转、淘汰、导出和清理路径必须测试失败行为。长期运行门禁需要测量日志自身写入；若预算明显改变被测结果，应降低事件密度或停止对应记录，而不是扩大配额。

## 6. 脱敏导出与反馈

用户主动触发“导出诊断”后，先看到文件类别、时间范围、预计大小和隐私说明。确认后生成 ZIP，文件名包含平台阶段、UTC 时间和随机运行标识。

ZIP 允许包含：

- `manifest.json`：契约版本、应用版本、平台与文件清单；
- `capabilities.json`：系统版本、架构、权限与功能状态；
- `events.ndjson`：限量生命周期、警告和错误；
- `summary.json`：ETW 丢失、受限数量、服务与存储健康摘要；
- `errors.json`：稳定错误码和原生数值；
- `privacy-check.json`：导出黑名单扫描结果。

ZIP 禁止包含历史 SQLite 数据库、原始 ETL、崩溃转储、PDB、EXE、用户名、SID、完整路径、命令行、文件内容或机器唯一标识。导出前后都执行隐私黑名单扫描；失败时不得生成可提交包。

“反馈问题”只打开项目 [GitHub Issues](https://github.com/HongXunPan/storpulse/issues/new) 与问题模板，预填应用版本、Windows 版本和稳定结果码。浏览器不会自动附加文件；用户自行检查并上传 ZIP。未来若增加自动反馈服务，必须另做隐私、鉴权、滥用、成本和删除策略决策。

## 7. 分阶段门禁

### 阶段 1：持续采集

- 完成 `RawSnapshot v2` 平台中立设备身份迁移；
- 连续协议、稳定进程身份、快照批量传输、stale 和错误状态通过测试；
- 服务断开、超时、停止、强杀和休眠恢复至少完成 Win10 实机门禁；
- 本地轮转、终止失败记录、导出和隐私扫描可复现；
- Win11 在取得实机证据前保持目标覆盖，不借用 Win10 结论。

### 阶段 2：实时纵切

- WinUI 3 列表虚拟化、通知区域、单实例和窗口生命周期通过实机门禁；
- 安装服务、受限状态、重新连接和诊断导出具有原生可访问界面；
- 关闭窗口后继续采样，退出应用后服务和 ETW 正确停止。

### 阶段 3：低写入闭环

- 历史默认关闭且不建库；启用后只批量保存分钟摘要和已结束活动；
- 提醒、保留期、清空和隐私导出复用共享语义；
- 普通日志、历史与服务失败记录的长期自身 I/O 达标；
- Win10 与 Win11 分别记录实机结果，未验证系统不得提升支持状态。
